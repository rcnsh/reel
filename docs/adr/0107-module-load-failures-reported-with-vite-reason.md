# Module load failures are reported with Vite's reason

When a project's module fails (a syntax error, an import of a file that is not there), the browser only learns that a load failed: "Failed to fetch dynamically imported module: <url>" for a scene's dynamic import, a refused script (`module did not load: <url>`, from `openPage` in `cli/renderer.ts`) for the static graph. `startServer` (`cli/server.ts`) captures Vite's transform errors through a custom logger (`onModuleError`), keyed by file, and `Renderer.explain` replaces each URL-only error with Vite's message for that file (the syntax error with its line and code frame, or the unresolved import), or says the file is not there. The logger uses the message, not `err.loc`: for a transform error the location points into Vite's own code, while the message carries the code frame.

A module of the page's static graph that fails to load (such as a config naming a scene file that is not there) means `main.ts` never runs, so `index.html`'s module script has an `onerror` that sets `window.__reel = { error }` and shows the error at once, instead of leaving the renderer waiting for a page that never becomes ready.

Vite's resolver remembers that a file was missing until the server restarts, and the fix for an unresolved import is usually a new file, not an edit to the importer. So after a module failed, `Renderer.rescan` marks the server for restart on the next change, and in the preview (`hmr`) `startServer` watches for an added file in the project after a failure and restarts Vite, after which the page reloads by itself.
